# v0.3.0 验收记录

日期：2026-09-26。工具链：Go 1.25.0，darwin/amd64。
框架基于已发布 v0.2.4 `368447b`，layout 基于已发布 v0.2.4 `9d3a894`，
均在独立 `codex/v0.3.0-release` worktree 收口；主工作区原有改名与 Migration v2 改动保留。

## 修复与 review

- 用户 panic 原本越过 rollback；已在事务边界内恢复，Result 和 VersionError 保留失败版本与原因。
- SQL Begin 原本使用 Background；已增加兼容的 BeginTxContext，验证连接池等待可取消。
- 取消后用户返回 nil 原本仍可能提交；已补提交前取消检查，清理使用独立 context。
- SQL 锁原本将所有 INSERT 错误当成竞争；现仅识别唯一约束冲突，其他错误保留原因。
- PostgreSQL 实库验证发现空密码的连接串解析错误；修复空值、空白、引号与反斜杠转义。
- 补齐正版本校验、SQL 历史空 duration 的读取、单次 SQL 连接 API 和 caller-owned 日志 writer。
- layout 移除无条件成功的 Fx migration hook，使用独立 run(ctx) 与 SQL 资源关闭路径。
- review 核对 Run/Plan/Status、状态优先级、SQL/Redis/Oracle transaction wrapper、命令参数、JSON、配置优先级、公开签名、生成模板与本版 diff。

使用专门的临时 PostgreSQL/MySQL/Redis 实例和 SQLite 文件，不连接用户现有业务数据库。
原始输出保存于本次 release evidence；失败基线也保留，以免只有最终成功日志。
macOS race 链接器有 LC_DYSYMTAB warning，相关测试退出码均为 0。

核心复验命令：

```sh
GOTOOLCHAIN=go1.25.0 GOWORK=off go test -race ./pkg/pi/migration ./pkg/pi/logging
GOTOOLCHAIN=go1.25.0 GOWORK=off go test ./pkg/pi -run 'TestApp_Migrate|TestMigrationV2API'
GOTOOLCHAIN=go1.25.0 GOWORK=off go build ./...
# layout 发布消费时
GOTOOLCHAIN=go1.25.0 GOWORK=off go test -race ./internal/migrationcmd ./test
GOTOOLCHAIN=go1.25.0 GOWORK=off go build ./...
```

实库测试通过 `PI_MIGRATION_TEST_mysql_*`、`PI_MIGRATION_TEST_postgres_*`
（HOST/PORT/USER/PASSWORD/NAME）及 `PI_MIGRATION_TEST_REDIS_ADDR` 显式启用。
必须使用可丢弃数据库：测试会重建其专用 migration/effects 表和 Redis 测试键。

## 范围与发布门禁

这是本版功能的验证，不是全库测试、全部 datasource 或外部集群认证。
未实测 Supabase/CockroachDB 服务与 Oracle 实例。MySQL DDL、Redis EXEC 和多后端部分成功
边界保留，锁无续租；详情见 [Migration v2 契约](../design/migration-v2.zh-CN.md)。

发版按框架 commit/tag → 公开 module 校验 → layout 依赖更新与 GOWORK=off 验证 → layout tag 执行。
最终 tag、commit、公开消费结果登记于 [开发计划发布记录](../../Pi_Development_TODO.md)。
