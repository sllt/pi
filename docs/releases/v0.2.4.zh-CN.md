# Pi v0.2.4 候选版

状态：本地开发与候选验证；尚未创建或发布 v0.2.4 tag。

## 本版变化

- HTTP Handler 的成功/error/panic 通过缓冲通道传递；外层不再并发读取可变的
  Context。迟到结果不会修改已经提交的响应。
- Start 一次执行，重复或并发调用复用启动结果；部分启动失败回滚已启动资源。
- Stop 只有一个执行者，其他调用者独立等待；缓存终态错误，超时不提前标为完成，
  Worker 退出后才关闭其依赖。
- 订阅 panic 转为处理错误，error/panic/已观察到的取消均不触发框架自动 Commit。
- pi-layout 默认不注册尚未完成身份和资源授权的 gRPC UserService，HTTP 用户入口继续可用。
- 框架 module、核心包、脚手架与 CLI 使用 Pi 名称。框架和 CLI 的候选版本均为 v0.2.4。

## 兼容说明

本候选从历史 v0.2.3 固定基线隔离，**保留旧版 Migration API**。主开发工作区内的
Migration v2、MigrateContext、plan/status/lock 等继续保留，属于 v0.3.0，未带入本版。

旧调用方需更新 module/import：`github.com/sllt/kite` → `github.com/sllt/pi`，
`pkg/kite` → `pkg/pi`。历史 tag 不重写，也不能假定旧 v0.2.3 已声明 Pi module。
迁移存储、锁键、限流键和既有 trace metadata 等持久化/协议标识保持兼容。
`PI_TELEMETRY` 优先，未设置时继续接受 `KITE_TELEMETRY`。

原有 Handler、Start/Stop/Shutdown 签名保持不变；HTTP 408、499、panic 的 500 和
普通响应封装规则保留。超时不会终止忽略取消的业务函数，也不会自动回滚业务副作用。

Start 的首个 context 仍是运行期父 context；后续 Start 仅控制自身等待。Stop 的
首个 context 提供执行预算，后续 Stop 仅控制自身等待。重复 Stop 现在保留原始失败，
因此不能再把“第二次返回 nil”作为忽略第一次关闭错误的方式。

默认 gRPC 用户入口关闭属于有意的安全行为变化。恢复前必须完成认证、资源授权、
业务校验和权限矩阵测试；仅设置 GRPC_PORT 不会启用它。

细节见 [生命周期契约](../design/adr-002-lifecycle-v024.zh-CN.md)、
[HTTP 所有权](../design/adr-003-http-response-ownership.zh-CN.md) 和
[订阅确认边界](../design/subscription-ack-v024.zh-CN.md)。

## 本版验收与范围

验收覆盖真实 Handler、路由、生命周期与订阅调用链的 race 测试，真实 HTTP
监听复用/启动失败回滚，以及 layout 默认装配、HTTP 登录和资料鉴权边界。
另在隔离候选中验证框架构建、CLI 版本和无 go.work/replace 的 layout 消费。

这不是全量外部数据库、消息集群、容器、所有独立 datasource module 的生产认证。
订阅保证的是框架自动 Commit 的条件，不是所有后端的重投递或 exactly-once 保证。
F01 仅缓解；跨协议授权、纯构造、完整 supervisor 和脚手架重构留待后续版本。
